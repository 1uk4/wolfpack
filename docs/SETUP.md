# Setting up (or rebuilding) your wolfpack

This repo is the **authoritative definition** of your wolfpack — it's your
"dotfiles" for a pack of AI agents. With a fresh clone, a fresh VPS, and this
guide, you can stand the whole thing back up.

---

## Mental model: what's in the repo vs. what you re-supply

The repo defines the **system**. A few things live *outside* it on purpose
(secrets and runtime state), and you re-supply or restore those on a rebuild.

| Thing | Where it lives | In the repo? | On a rebuild |
| --- | --- | --- | --- |
| CLI, agent, extensions, profiles | this repo | ✅ yes | `git clone` + `./install.sh` |
| `ANTHROPIC_API_KEY` | `~/.wolfpack/.env` | ❌ no (secret) | re-enter |
| SSH key for hosts | `~/.ssh/wolfpack` | ❌ no (secret) | regenerate + re-authorize |
| Host registry + agent API keys | `~/.wolfpack/config.yaml`, `~/.wolfpack/keys/` | ❌ no | regenerated by `host add` |
| Tailscale membership | the VPS + your tailnet | ❌ no | `tailscale up` per host |
| Telegram bot tokens + owner id | BotFather + wolf `.env` | ❌ no (secret) | re-enter at `add wolf` |
| Wolf **dens** (memory) | VPS `/home/wolf-<id>/den`, mirrored to Mac | ❌ no (runtime) | restore from backup mirror |

So: **the repo + your secrets + a backup of the dens = your whole pack.**

## Prerequisites

- A control machine (your Mac/Linux laptop) with **git** and **Node 22+**
  (Pi 1.0.x requires Node 22). With nvm:
  ```bash
  nvm install 22 && nvm alias default 22
  ```
- An **Anthropic API key**.
- A **Tailscale** account (free tier is fine).
- A **VPS provider** account (Hetzner, DigitalOcean, Vultr, Fly.io, …).
- A **Telegram** account (for 24/7 assistant wolves).

---

## Part 1 — Local control plane (the Mac)

The Mac is the *management plane*. It never runs 24/7 wolves itself; it builds
them and talks to the VPS agents.

```bash
git clone git@github.com:1uk4/wolfpack.git
cd wolfpack
./install.sh
```

`install.sh` will:
1. verify Node 22+,
2. `npm install` + `npm run build` + link the `wolfpack` CLI globally,
3. install the `pi` runtime globally,
4. scaffold `~/.wolfpack/` (shared secrets + host keys),
5. check for an SSH key.

Then finish the two secrets it can't create for you:

```bash
# 1. Provider key (shared by every wolf + the memory system)
$EDITOR ~/.wolfpack/.env         # set ANTHROPIC_API_KEY=sk-ant-...

# 2. SSH key for reaching VPS hosts (if you don't have one)
ssh-keygen -t ed25519 -f ~/.ssh/wolfpack
```

**(Optional) a local worker wolf** — a keyboard-driven agent on the Mac:
```bash
wolfpack add wolf myname          # worker profile: memory + subagents
wolfpack launch myname            # runs pi AS the wolf in your current dir
```

## Part 2 — A VPS host

Each VPS is a **host** that runs the wolfpack agent and one or more 24/7 wolves.

### 2a. Create + join the tailnet

1. Spin up a VPS: **Ubuntu 22.04/24.04 LTS, 2 GB+ RAM**.
2. SSH in as root and join Tailscale:
   ```bash
   ssh root@<provider-ip>
   apt-get update && apt-get -y upgrade
   curl -fsSL https://tailscale.com/install.sh | sh
   tailscale up                    # follow the auth URL
   tailscale ip -4                 # note this tailnet IP
   ```
3. Authorize your SSH key (from the Mac):
   ```bash
   ssh-copy-id -i ~/.ssh/wolfpack.pub root@<tailscale-ip>
   ```

> The agent runs as **root** (it manages per-wolf unix users + systemd), so SSH
> as root or a user with passwordless sudo.

### 2b. Register + provision

```bash
wolfpack host add wolf-01 --ip <tailscale-ip>
```

The wizard runs pre-flight checks, then the deploy installs **Node 22 → pi →
Tailscale → Syncthing → the wolfpack agent** (systemd, port 3141, tailnet-only),
saving a generated agent API key to `~/.wolfpack/keys/wolf-01.key`.

> Running `wolfpack host add wolf-01` with no `--ip` opens the guided wizard,
> which prints these same steps if the box isn't ready yet.

Verify:
```bash
wolfpack host status wolf-01      # CPU/mem/disk + Tailscale + Syncthing + wolves
```

## Part 3 — Wolves

### A 24/7 assistant wolf on Telegram

1. **Create the bot:** open [@BotFather](https://t.me/BotFather) → `/newbot` →
   copy the token.
2. **Get your owner id:** message [@userinfobot](https://t.me/userinfobot) → note
   the numeric id (pre-pairs the bot to you; otherwise the first `/start` pairs).
3. **Create the wolf:**
   ```bash
   wolfpack add wolf aide --host wolf-01
   # assistant profile → prompts for bot token + owner id
   ```
   The CLI builds the identity bundle (extensions + settings + persona), ships it
   to the agent, which provisions `wolf-<id>`, writes its `.env`, and starts
   `pi --mode rpc` under systemd. The Telegram extension **auto-connects** on
   boot from the env token.
4. **Test the round-trip:** DM your bot `/start`, then send a message.

### A local worker wolf

```bash
wolfpack add wolf myname          # worker profile
wolfpack launch myname [project-dir]
```

### Propagating extension updates

Edit an extension in `extensions/`, or add one to a wolf, then push it:
```bash
wolfpack config aide --set extensions=memory,subagents,telegram
wolfpack sync aide                # rebuild bundle + restart; den/sessions preserved
wolfpack sync --all              # every wolf on every host
```
`wolfpack status <wolf>` shows each extension's version and flags drift
(`out of date → vX`) when a wolf is behind the repo.

## Part 4 — Day-to-day

```bash
wolfpack list                     # all wolves, local + every host
wolfpack status <wolf> [--host h] # service state + memory snapshot + ext drift
wolfpack logs <wolf> [-f]         # journald via the agent
wolfpack restart <wolf> --host h
wolfpack host status <host>       # host health
```

## Part 5 — Rebuilding from scratch (disaster recovery)

New Mac, new VPS, nothing but this repo and your secrets:

1. **Control plane:** `git clone` → `./install.sh` → fill `~/.wolfpack/.env`
   (`ANTHROPIC_API_KEY`) → regenerate `~/.ssh/wolfpack` and re-authorize it on
   hosts.
2. **Host:** new VPS → `tailscale up` → `wolfpack host add <host> --ip <ip>`
   (reinstalls everything; mints a fresh agent API key).
3. **Wolves:** `wolfpack add wolf <name> --host <host>` with the bot token again.
4. **Memory:** restore each wolf's `den/` from your backup mirror
   (`~/wolves/<host>/<wolf>/`) / Syncthing into `/home/wolf-<id>/den` on the VPS,
   then `wolfpack restart <wolf> --host <host>`.

Everything except the secrets and the dens is reproduced from the repo.

## Reference

- **Architecture + layout:** see [`README.md`](../README.md).
- **Shared secrets:** `~/.wolfpack/.env` (`ANTHROPIC_API_KEY`).
- **Per-wolf env** (written at creation): `WOLF_ID`, `WOLF_NAME`, `WOLF_DEN`,
  `WOLF_MODEL`, `WOLFPACK_LIBRARIAN`, and (assistant) `TELEGRAM_BOT_TOKEN` /
  `TELEGRAM_OWNER_ID`.
- **Ports:** agent HTTP `:3141` (tailnet-only), Syncthing `:8384`.
